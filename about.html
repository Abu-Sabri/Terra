04 · About

How this was built

TerraLive is a small live dashboard. It has five pages, one stylesheet, four short JavaScript files and no server of its own — every number on screen is downloaded straight into the browser.

The aim was to show that "live data" does not need a big framework. A page asks a public API for the newest numbers, receives them as JSON, and writes them into elements that are already in the HTML. When the data is new, the page simply repeats that cycle — once a second for the clock, every five seconds for the space station, every five minutes for earthquakes.

02 The three data sources

USGS — earthquakes

earthquake.usgs.gov

A GeoJSON file containing every event of the last 24 hours. Each feature has a magnitude, a place name, a time and coordinates with a depth. Free, no key, updated every minute.

Open-Meteo — weather & air

api.open-meteo.com

Two endpoints: one for temperature, wind, pressure, UV and sunrise, one for the US air-quality index and pollutant levels. You send a latitude and longitude, you get back the forecast.

Where the ISS at? — orbit

api.wheretheiss.at

One JSON object per request with the station's latitude, longitude, altitude, speed and whether it is in sunlight. The page asks again every five seconds.

03 One data cycle, in code

Wait for the answer

async tells JavaScript the function will wait for something. await pauses only this function — the rest of the page keeps running. 

// common.js
async function fetchJSON(url) {
  const response = await fetch(url);
  if (!response.ok) throw new Error("failed");
  return response.json();
}

Use the answer

The station's numbers arrive as one object, so they are copied straight into the elements that show them — no rebuilding of the page. 

// iss.js
const data = await fetchJSON(API.iss);
$("iss-lat").textContent =
  formatLatLon(data.latitude, true);
$("iss-alt").textContent =
  Math.round(data.altitude) + " km";

try / catch wraps every request: if the API is unreachable the page shows "offline" in the status pill instead of going blank.

04 Questions, answered

Where does the data come from?

Three public APIs, all free and keyless: USGS for earthquakes, Open-Meteo for weather and air quality, and WhereTheISS.at for the station. The addresses are all listed at the top of common.js in one object called API.

Why is there no backend?

Because these APIs send the header Access-Control-Allow-Origin, which allows a browser to call them directly. So the browser is the client and the thing that draws the page — no PHP, Node or database is involved.

How does the page update itself?

Two timers. setInterval(tick, 1000) redraws the clock once a second, and setInterval(fetchISS, 5000) asks for a new position every five seconds. The earthquake feed is reloaded every five minutes. Each tick replaces text, not the whole page — which is why nothing flickers.

How are the earthquakes drawn on the map?

Leaflet is the only library used. For each event we create a L.circleMarker at its coordinates. Its radius comes from the magnitude and its colour from the same number, so the strongest events are the biggest and brightest.

Why do the filter buttons not lose any data?

The full list is stored once in the quakes array. Filtering uses .filter() and sorting uses .sort(), both of which return a new array. The original list is never touched, so pressing "ALL" brings everything back instantly without another download.

What happens when the internet is down?

Every request sits inside try / catch. If it fails, the status pill turns red and says "offline", the weather page shows a red banner, and in the worst case the map area says that the map library has to come from a CDN. Nothing white-screens.

How is the city list handled?

cities.js holds about 280 places as plain objects. The search box is an <input list="city-options"> connected to a <datalist>: the browser itself provides the matching drop-down, so the JavaScript only has to find the chosen name in the array and fetch that city's weather.

How long is the code?

Roughly 1,200 lines of CSS and 1,000 lines of JavaScript, comments included. The longest single function is under 30 lines, and every file starts with a note saying what it is for.

05 Limits of the project

It needs a connection

Open the folder with a double-click and the layout still works, but the numbers need the APIs and the map needs the Leaflet files from a CDN. Serving the folder over HTTP (or putting it online) is the smoothest way to show it.

Earthquakes are not instant

The USGS feed is a summary that updates about once a minute, so a very fresh event can take a moment to appear. That is the data source, not the page.

Air quality is a model

Open-Meteo's air-quality figures are modelled from monitoring stations, not measured at your street. The category labels follow the official US AQI bands.

Nothing is stored

There is no database and no localStorage: reload the page and it asks the APIs again. That keeps the project easy to reason about — the page is a view of the data, nothing more.
