About TerraLive

TerraLive is a university web development project that turns three free, public, real-time data sources into one dark-themed "command center" dashboard — using nothing but HTML5, CSS3, vanilla JavaScript and the Leaflet mapping library.

STATIC PAGE · NO FETCH

Purpose

The goal of this project is to demonstrate end-to-end competence with the native building blocks of the web: semantic HTML for structure, CSS custom properties and grid/flexbox for a responsive "mission control" interface, and vanilla JavaScript for everything dynamic. All live behaviour comes from the browser's built-in fetch() method and the setInterval() timer — there is no framework, no bundler, no package.json and no build step between the source files and the browser.

Each of the three data "nodes" (seismic, atmospheric, orbital) consumes a different public REST API that returns JSON over HTTPS. The APIs were chosen deliberately: they are free, they require no API key or registration, and they send permissive CORS headers — which means the exact code in this project runs identically whether it is opened from a local folder or hosted on any static web server.

How the Asynchronous fetch() Cycle Works

Every node in TerraLive follows the same six-step cycle. Walking an examiner through these steps while pointing at the commented fetchJSON() helper in script.js covers the whole asynchronous story:

  1. Trigger. Something starts the cycle: the page loads (DOMContentLoaded), a timer fires (setInterval — every 5 s for the ISS, every 5 min for earthquakes) or the user clicks Resync.
  2. fetch() returns a Promise immediately. fetch(url) asks the browser to send an HTTP GET request and hands back a Promise — a placeholder object for a result that will arrive later. JavaScript does not stop and wait.
  3. await suspends only this function. Inside an async function, await pauses just that function until the response arrives. The rest of the page stays fully responsive — the event loop keeps handling clicks, hovers and animation frames.
  4. The body is parsed as JSON. response.json() returns a second Promise that resolves with a native JavaScript object built from the API's JSON text. We then read plain properties such as data.current.temperature_2m or feature.geometry.coordinates.
  5. Render. Values are written into the page with textContent / innerHTML, and geographical values are turned into Leaflet markers, circles and polyline trails.
  6. Handle failure. The whole cycle sits inside try … catch, so a network error or a bad status code flips the node's status pill to "OFFLINE" instead of crashing the page — and the next timer tick automatically retries.

On the weather page the cycle is run twice in parallel using Promise.all([...]), and on the home page all three node summaries are started together with Promise.allSettled([...]) so that one failing API can never block the other two — both are worth pointing out in a demonstration.

Technology Stack

  • HTML5 — semantic landmarks (header / nav / main / section / footer), one data attribute per page (body[data-page]) for script routing.
  • CSS3 — custom properties for the whole colour system, grid & flexbox layouts, keyframe animations (pulsing status dots), and media queries at 1000 px / 880 px / 640 px for full responsiveness.
  • Vanilla JavaScript (ES2020) — async / await, fetch(), template literals, arrow functions, optional chaining and a single shared script.js routed per page.
  • Leaflet 1.9.4 (CDN) — the only external library: dark CARTO basemaps, circle markers scaled by magnitude, a custom pulsing ISS marker, footprint circles and polyline ground trails.
  • Google Fonts (CDN) — Orbitron, Rajdhani and JetBrains Mono for the command-centre typography (with system-font fallbacks if offline).
